# 全库一键导入播放列表

## Goal

在 Windows 版 Navidrome 浏览器中增加独立的“添加全部”按钮，让用户无需展开或逐个选择约 1128 位艺术家，即可把完整音乐库中可访问的歌曲一次性追加到 foobar2000 当前播放列表。

## User Value

- 将逐个艺术家重复操作改为一次操作。
- 保留现有单项添加和立即播放习惯，不要求用户学习 Ctrl/Shift 多选。
- 对可能持续较长时间的全库网络递归提供明确进度，避免误判卡死或重复点击。

## Confirmed Facts

- Windows 树控件使用标准单选 TreeView，未配置可用的原生多选能力（`Windows/BrowserWindow.cpp:74-79`）；当前选择收集逻辑也按单选工作（`Windows/BrowserWindow.cpp:348-361`）。
- 单项添加已经具备后台递归路径：`queueSelected` 在后台线程调用 `collectSongsDeep`，完成后回到 foobar2000 主线程追加播放列表（`Windows/BrowserWindow.cpp:364-380`）。
- 递归仅能通过 `getAlbumsForArtist` 和 `getSongsForAlbum` 分层请求；客户端没有一次获取完整音乐库歌曲的批量 API（`Windows/SubsonicClientWin.h:17-20`）。
- 播放列表条目必须继续由 `makeTrackURI` 生成 `navidrome://track/...` URI，并通过现有元数据提示及 `playlist_add_items` 一次写入（`Windows/BrowserWindow.cpp:509-564`）。
- 当前顶层艺术家/搜索结果共用 `m_rootNodes`（`Windows/BrowserWindow.h:116-118`），因此全库入口需要保存独立的完整艺术家根集合，不能把当前搜索结果误当成全库。
- Windows 用户可见字符串必须集中在 `Windows/Localization.h`，布局变化必须保持窄窗口和高 DPI 下的非负尺寸（`.trellis/spec/frontend/windows-localization.md`）。

## Requirements

### R1. 独立全库入口

- 在现有“添加到播放列表”和“立即播放”旁新增“添加全部”按钮。
- 按钮作用于最近一次成功加载的完整艺术家集合，与当前选中节点、展开状态和搜索结果无关。
- 完整艺术家列表尚未加载成功时，“添加全部”不可触发。

### R2. 复用现有递归和播放列表契约

- 单项添加、立即播放和全库添加必须进入同一组根节点队列处理路径，避免复制递归及播放列表逻辑。
- 全库任务按艺术家、专辑、歌曲的服务器返回顺序收集歌曲。
- 收集完成后一次性追加到当前播放列表；任务取消时不追加半成品。
- 不改变 URI、元数据、活动播放列表创建或现有播放顺序行为。

### R3. 后台执行和进度

- 所有 Navidrome 网络递归继续在后台执行，foobar2000 UI 主线程保持可响应。
- 全库任务至少显示“已处理艺术家数/艺术家总数”和“已找到歌曲数”。
- 任务进行期间禁用会启动另一项加载/入队操作的控件，且所有快捷键、右键菜单处理函数也必须拒绝重复启动。

### R4. 生命周期和取消

- 后台任务不得捕获并在窗口销毁后访问裸 `BrowserWindow*`。
- 关闭独立窗口或偏好设置页时设置取消标记；后台任务在网络调用之间检查标记并丢弃未完成结果。
- MVP 不增加单独的“取消”按钮。

### R5. 错误与重复语义

- 单个艺术家或专辑请求失败时记录失败项并继续其余根节点。
- 若收集到歌曲，则一次性追加成功歌曲并显示“已添加歌曲数 + 失败项数”的汇总；若未收集到歌曲，则不得修改播放列表。
- 防止同一窗口内并发重复触发；前一次任务完成后再次点击仍按现有追加语义重新加入，不扫描或去重当前播放列表。

### R6. Windows 汉化和布局

- 新按钮、进度、忙碌和部分失败文本统一加入 `navidrome::l10n`。
- 四个动作按钮和状态区在独立窗口及嵌入偏好设置页中保持可用，紧凑计算不得产生负宽度。
- 仅修改 Windows 组件。

## Acceptance Criteria

- [ ] AC1：完整艺术家列表加载后，不选择、不展开任何节点也能点击“添加全部”启动任务。
- [ ] AC2：任务遍历完整艺术家根集合，并把所有成功获取的歌曲以现有 `navidrome://track/...` 格式一次性追加到当前播放列表。
- [ ] AC3：大库导入期间窗口保持响应，状态区持续显示已处理艺术家数、总数和已找到歌曲数。
- [ ] AC4：任务进行期间，按钮、Enter、右键菜单或双击均不能启动第二个并发入队任务；完成后控件恢复。
- [ ] AC5：一个艺术家或专辑失败不会终止其余导入；完成状态同时报告成功歌曲数与失败项数。全部失败或零歌曲时不修改播放列表。
- [ ] AC6：任务中关闭窗口/偏好页不会发生失效窗口访问，未完成任务不会追加半成品。
- [ ] AC7：原有单项“添加到播放列表”“立即播放”、Enter、右键菜单、搜索、刷新和歌曲 URI/元数据行为不回归。
- [ ] AC8：Windows `Release|x64` 构建为 0 错误，并生成新的独立 DLL 与 `.fb2k-component` 安装包；旧的汉化构建产物保留。

## Out of Scope

- Ctrl/Shift 手工多选、自绘多选 TreeView 或选择部分顶层艺术家后批量导入。
- “添加全部搜索结果”或根据当前过滤视图改变“添加全部”的含义。
- 扫描现有播放列表并去重、服务端批量导出 API、离线缓存或播放列表同步。
- 用户可见的独立取消按钮。
- macOS/Linux 界面和构建。

## Key Decisions

- 使用独立“添加全部”按钮，不模拟原生 TreeView 不支持的多选交互。
- “全部”固定表示完整音乐库，而不是当前搜索结果。
- 全部歌曲收集成功或部分成功后再进行一次播放列表写入，以避免取消时留下半成品。
- 请求失败采用“继续并汇总”，重复添加采用现有的“再次追加”语义。
